# 前人的痕迹（legacy-life）

一个类似《80 亿分之 1》的人生模拟原型，加上**第 1 级异步互动**：前面玩家的选择，会变成后面玩家人生里的事件。

## 运行

```bash
npm start          # http://localhost:3000，数据存在 data/db.json
npm test           # 引擎 + API 测试
PORT=8080 DB_FILE=/tmp/db.json npm start
```

需要 Node 20 以上，没有任何依赖。

## 玩法

1. 按各国年新生儿数加权，随机投胎到 11 个国家之一。
2. 一年一年往前推进，按该国统计（预期寿命、五岁以下死亡率、入学率、收入档位）决定生死和机会。
3. 12 岁、18 岁、22 岁、恋爱、40 岁、临终时做选择。
4. **40 岁时可以给城市留下一份遗产**：小店、学校、诊所或树林。**临终时可以给未来的陌生人留一张纸条**（从预设句子里选）。
5. 后来投胎到**同一个国家**的玩家会遇到你的遗产：在你的诊所出生、在你的学校上学、在你的店里找到第一份工作、在你种的树林散步。纸条**跨国**出现。
6. 每一生都有分享链接 `/?life=<id>`，能看到"你留下的东西改变了谁"。首页会列出你活过的人生和它们的影响人数（存在 localStorage）。

## 结构

```
shared/data.js     国家统计（近似值）、职业、遗产类型、预设纸条
shared/engine.js   模拟引擎：纯函数 + 生成器，前后端共用
server.js          静态文件 + 3 个 API + JSON 文件存储
public/            原生 JS 前端
test/              node:test
```

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/legacies?country=IN` | 该国最多 40 份遗产 + 任意国家的 10 张纸条（随机抽样） |
| POST | `/api/lives` | 提交一生的结构化结果，存档并写入遗产，同时给被碰到的遗产记一次"影响" |
| GET | `/api/lives/:id` | 一生的摘要、留下的遗产及其影响、改变过它的前人 |

### 互动是怎么连起来的

- 开局时客户端拉一次遗产，引擎在模拟中按条件把它们挂成事件，并在 `touched` 里记下 id。
- 结束时提交一次，服务端反向写入 `legacy.impacts`。全程只有一读一写，不需要实时连接，也不需要别的玩家在线。
- 冷启动：首次启动会给每个国家生成种子遗产（`npc: true`），真实玩家的遗产被抽中的权重是种子的 3 倍。

### 安全取舍

- 玩家**没有任何自由文本**：名字、城市、职业、纸条都必须在预设表里，摘要由服务端重新生成，所以不需要内容审核。
- 服务端对每个字段都按数据表校验，遗产只能挂到同一个国家（纸条除外）。
- **还没做的**：模拟在客户端运行，有心人可以伪造一个"合法但不真实"的人生（比如任意选择遗产类型）。要彻底防作弊，需要把引擎放到服务端运行（引擎本来就是纯函数，可以直接搬过去），或者让客户端提交种子和选择序列，由服务端重放验证。另外也还没做限流。

## 数据说明

`shared/data.js` 里的数值是按联合国、WHO、世界银行公开数据粗略取整的示意值，只够原型使用。死亡概率用的是按预期寿命校准的 Gompertz 曲线，加上五岁以下死亡率。
